## What SuperGrok2 is
A portable, self-designing PyTorch-shaped training stack (Python front-end + CUDA/C++ backend) that benchmarks **11 optimizers × 3 ~1.5B flagships** (decoder d=1600/L48, ViT d=1664/L48, Mamba-3 d=2048/L24) on a grokking task (modular arithmetic mod p=97; cold-start loss ≈ ln 97 = 4.575). The backend self-specializes the kernel to any workload via compile-time templates. Repo at `/workspace/SuperGrok1.5`, branch `claude/custom-optimizer-analysis-HFYhg`, **HEAD 0668904** (5 docs/cache commits past the closure code-HEAD **03bd3f0**; `git log 03bd3f0..HEAD -- csrc/` is empty, so kernel state == 03bd3f0).

## Megakernel substrate (the real path)
One **persistent, non-cooperative** launch `fused_decoder_megakernel_tc<Opt,Par>` at `gridDim=#SMs`, 1 CTA/SM, 256 threads, coordinated by a hand-built **sense-reversing GridBarrier** (`megakernel_common.cuh:147-255`, two atomics + generation counter, `__nanosleep` backoff, 2 fences/CTA; NO cooperative launch). Phase skeleton: P0 zero → B0 → P1 fwd+bwd (acts→HBM) → B1 (+B1b for dW operands) → P2 **ascending-CTA fixed-order fp32 dW reduce** → B2 `sync_reset` → P3 per-element `apply_optimizer<Opt>` (`opt_components.cuh:380-520`). GEMMs are hand-rolled in-kernel **ss-wgmma** `m64nNk16.f32.bf16.bf16` (`wgmma.cuh`), cp.async ring, **no TMA, no CUTLASS collective**. Only 4 sm_90 fused TUs compile into `_ops` (the 3 per-model `_tc_launcher.cu` + `sg2_meta_tail.cu`); each launcher is `switch(OptId)` over a templated launch.

## Real distributed/parallel state
**Mesh dimensionality.** `ParConfig<DP,TP,PP,SP,Z,EP=1>` (`parallel_config.cuh:74`) is 5-axis+ZeRO. Live in-kernel: **only TP** (74 `kTPComm` sites). **SP** hard-pinned `static_assert(SP==1)` (`:99`). **EP** expressible-only (`kEPComm` no kernel consumer, never EP>1). **PP** in-kernel is also expressible-only (`kPPStage` has no consumer; every instantiation PP=1). Single instantiated multi-GPU geometry: `ParConfig<8,8,1,1,Z3>` (DP8×TP8, `mega_decoder_..._launcher.cu:238-240`); **DP=8 is a sentinel** (no DP cross-rank reduction exercised at world=8).

**TP datapath.** Genuine Megatron sharding is committed (c80a905 attention head-shard, 5733af5 EDIT A/B/C, 531d87e remainder): qkv/ff0 column-shard `(3*kD)/kTP` & `kDff/kTP` (`model_stage_decoder_tc.cuh:2139,2216,2393`), out_proj/ff2 row-shard, attention head-localized `Hloc=kHeads/kTP, Dloc=kD/kTP` (`:1528,:1839,:2156`). Exactly **4 activation all-reduces** (out_proj fwd, ff2 fwd, ff0-dX bwd, in_proj-dX bwd) via `tp_allreduce_sum_fixed_order` (`tp_transport.cuh:243-256`, ascending-pe fp32, `#pragma unroll 1`, deliberately NOT `nvshmem_float_sum_reduce`). Transport is compile-selected: real `NvshmemTransport` (`nvshmem_ptr` NVLink + `nvshmemx_barrier_block(tp_team)`, `:191-222`) under `-DSG_HAS_NVSHMEM`, else single-grid `LoopbackTransport` (`:118-158`).

**Three load-bearing defects in the committed TP path:**
1. **Forward weight cache is degenerate.** `dectc_wbf_convert` (`:570`) caches the full `[3d,d]` in_proj weight replicated on every rank and `dectc_gemm_fwd` reads the first `3d/P` rows (q-prefix, not `[q_own|k_own|v_own]`); `tp_rank` appears nowhere in the file. So forward weight **memory is not reduced** and the read is **mis-aligned for P>1**. The faithful per-rank shard (`tp_layer.cuh:165-207 tp_colqkv_fwd_tile`, host-packed `[3d/P,d]`) is the **standalone loopback deliverable, not wired into the megakernel**.
2. **Megakernel dW path is structurally broken (UNVERIFIED, highest-risk).** `dectc_build_dw_specs` (`:2660-2685`) is **not** `Par`-templated: it sets `sp.Nout=3*kD`/`kDff` (full) and reads `dY_qkv`/`dY_ff0` at full stride, but the backward wrote those at **sharded** stride (`:2461,:2405`). Because `dec_acts_bind` (`:443-463`) always over-allocates full width, the full-`Nout` reads stay in-bounds and **corrupt the never-written upper 7/8 as gradient** (rather than faulting), with **no grad all-reduce of the sharded slices**. The "backward confirmed" verdict only validated `tp_layer.cuh`'s loopback dW (`test_tp_loopback.py`), NOT this path.
3. **Head divisibility.** `Hloc=kHeads/TP` integer-divides. Flagship kHeads=25 @ TP=8 → **Hloc=3 (drops 1 of 25 heads)** — NOT a silent zero (Hloc=0 only when kHeads<TP, e.g. default kHeads=4).

**Host weight-shard + NVSHMEM bootstrap (spans two commits).** `distributed.py:846-931 partition_tensor_parallel` is a **metadata-only** Megatron plan (per-rank Nmax=kDecMaxTensorNumel/TP=1.28M @ TP8; never slices tensor data; **decoder-only**, raises for vit/mamba). The NVSHMEM bringup in **d3c0b88 only PLANS** (`host_bringup.py:260` raises `TPBootstrapBlocked`); the **live pybind** (UID init + `nvshmem_team_split_strided` + `nvshmem_malloc`) landed in the **later 03bd3f0** (`nvshmem_bringup_pybind.cpp:135,183,225`). HW-proven cross-rank all-reduce at 2/4 GPUs; 8-GPU blocked by co-tenancy (NVLS cuMemMap forbidden).

**PP / ZeRO-3.** PP Python (`pipeline.py`) is a real, CPU-tested 1F1B schedule (41/41), disjoint stage ownership, but **LoopbackP2P only** (no real multi-GPU P2P); the CUDA half (`pp_stage_decoder_tc.cuh`) `#error`s without the unapplied+stale `SG_DECTC_LAYER_RANGE` patch (the production tile signature gained a `wb` param after the patch was authored). ## Resource-planner brain + memory levers (per model)
Four pure-Python planning modules (`resource_planner.py` escalation ladder, `auto_config.py` mesh selector, `mem_strategy.py`, `flagship_budget.py`) emit a per-rank HBM/scratch budget + `-D` knobs before any GPU work. **Only `cta_tiling` (nCTA) is genuinely wired** in all 3 kernels. **zero3** is partial (Z3 + the separate host-driven sharded kernel; in-megakernel gates unread). **recompute / layer_stream / host_offload are emitted-but-unimplemented for all 3** (`mem_config.cuh` `#included` nowhere; `SG_DEC_*`/`SG_MEM_*` consumed in 0 csrc files). Caveats: the decoder always recomputes fwd-in-bwd as inherent one-layer-live design (not a planner toggle); mamba's `kMbStreamSmem` is an **auto** smem-overflow-to-HBM gate (not planner-driven, dead at d≤1024, active only at flagship). Two duplicated budget engines (`resource_planner.py` vs `flagship_budget.py` + `mem_strategy.py`) claim to mirror `dec_tc_*_floats` but were never cross-checked for agreement (drift risk; `mem_strategy.py` docstring even wrongly says `flagship_budget` is absent).

## Optimizer reality
All 11 `apply_optimizer<OptId>` branches (`opt_components.cuh:380-520`) are **real, distinct device math with no AdamW fallback** — the old "7-of-11-are-secretly-AdamW" defect is gone. The single residual stub is the elementwise `apply_optimizer<SuperGrok2>` (`:511-519`, Adam-on-smart_grad), and it is **bypassed in production**: SG2 routes through the in-kernel P3-SG2 phase → `sg2_meta_stages` → `sg2_apply_step` in all three megakernels (decoder `:1413`, vit `:1065`, mamba `:1146`), running the full CSA/HCA/PEER/matrix-GRU meta-net + in-kernel bitonic sort. SG11 has a real `sigmoid(gate_temp·cos)` gate (not a clamp). **Caveat:** `supergrok2_bilevel_adjoint.h` (the meta-learning reverse-mode VJP, 24 weight-grad buffers) is **orphaned — no csrc include, not in `_ops`** — so the SG2 meta-net forward runs on whatever weights are loaded; the meta-net is not actually trained. All static-verified by file:line; no compile/numeric parity re-run at HEAD, and the per-op reference SG2 was checked against was subsequently deleted.
