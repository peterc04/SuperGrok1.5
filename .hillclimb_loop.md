# Hill-climb loop infra — d-scaled decoder persistent megakernel (task #13)

The L3-TC persistent megakernel (fwd+bwd+opt fused, wgmma) is proven END-TO-END at
**d=1024** on the decoder (parity 2.4e-07, A/A/A) but runs at **~0.49% of the bf16
compute roofline** at both d=128 and d=1024 (d=1024: ~4.9 TF/s, ~0.5 steps/s @
B=16384 — ~2 s/step for work 30% MFU would do in ~33 ms). This file is the
**hill-climb loop**: how to edit the kernel, rebuild ONLY the d-scaled bench variant
(not production), and measure one iteration — without redoing throwaway codegen or
touching the production `_ops.so` / the 33/33 gate.

Repo root for all commands: `/workspace/SuperGrok1.5` (run from there).

---

## The coexisting bench-variant build (Deliverable A)

The d-scaled benchmark is a **first-class coexisting build**, not a regen-and-revert:

- **One generated header, two layouts.** `csrc/fused/sm_90/decoder_layout.cuh` now
  carries BOTH the production **d=128** layout (the `#else` branch — byte-identical to
  the historical header) and the **d=1024** bench layout (the `#if SG_DEC_BENCH_LAYOUT`
  branch), under one include guard. The compile flag `-DSG_DEC_BENCH_LAYOUT=1` selects
  d=1024; **unset → d=128**. The production `_ops` never passes the flag, so it is
  unaffected, and the committed tree stays at d=128. Single source of truth is still
  `grokking_optimizers/megakernel_codegen.py` `_decoder_param_sizes(d)` /
  `_DEC_BENCH_D` — regenerate with:
  ```
  python -m grokking_optimizers.megakernel_codegen --decoder-layout > csrc/fused/sm_90/decoder_layout.cuh
  ```
  (only needed if you change a model dim or the bench width; the d=128 branch must
  stay byte-identical — see "Guardrails" below).

- **Separate extension module + own build dir.** The bench variant is the SAME decoder
  TC cell TU (`csrc/fused/sm_90/mega_decoder_real_adamw_tc.cu`, the standalone-JIT cell
  that already owns its own `PYBIND11_MODULE` and is EXCLUDED from `_ops` by setup.py's
  `_owns_extension_module` filter), JIT-compiled by `tuning/decoder_bench.py` under a
  **distinct module name** (`mega_decoder_real_adamw_tc_bench[_prof]`) into its own
  `torch_extensions` build dir. That gives **ninja incremental rebuild + sccache** for
  free: editing the shared kernel header (`fused_decoder_megakernel.cuh`) and re-running
  the driver recompiles only this TU, in seconds-to-low-minutes, with zero impact on
  `_ops.so`.

- **Production stays green & committable.** `decoder_layout.cuh` is committed at d=128
  (the bench numbers live in the inactive `#if` branch). The kernel instrumentation
  (`SG_DEC_PROFILE`, below) is default-OFF, so the production path is byte-identical.

## ONE hill-climb iteration: edit → rebuild variant → measure

The hill-climb target is the **kernel structure** in the shared headers
(`csrc/fused/sm_90/fused_decoder_megakernel.cuh`,
`csrc/fused/sm_90/model_stage_decoder_tc.cuh`). The d value is fixed in the layout
header's bench branch; you do NOT re-edit it each iteration.

1. **Edit** the shared kernel header (the GEMM K-loop, split-K, barrier sequence, …).

2. **Rebuild the variant + measure throughput** (B=16384, the measured config; the JIT
   `load()` rebuilds incrementally — only changed TUs recompile):
   ```
   CUDA_MPS_PIPE_DIRECTORY=/nonexistent PYTHONPATH=. \
     python tuning/decoder_bench.py --d 1024 --B 16384 --reps 3
   ```
   Reports: wall/step (ms, median of reps), steps/s, achieved TF/s, % of the 989 TF/s
   bf16 dense roofline.

3. **(Diagnosis) Per-phase wall breakdown** — adds the in-kernel clock64 timers
   (`-DSG_DEC_PROFILE=1`, a SEPARATE variant module so the throughput number stays
   un-perturbed):
   ```
   CUDA_MPS_PIPE_DIRECTORY=/nonexistent PYTHONPATH=. \
     python tuning/decoder_bench.py --profile --d 1024 --B 16384 --reps 3
   CUDA_MPS_PIPE_DIRECTORY=/nonexistent PYTHONPATH=. \
     python tuning/decoder_bench.py --profile --d 1024 --B 2048  --reps 3   # small-B
   ```
   Prints the per-phase ms + % table (P1 fwd / P1 bwd / B0+B1+B2 grid barriers / P2
   dW-GEMM / P2 grad-assembly / P3 opt tail) and the DOMINANT phase.

4. **ncu section metrics for the launch** (optional, WHERE cycles stall — the megakernel
   is ONE launch so this is per-launch totals, the most informative single instrument):
   ```
   CUDA_MPS_PIPE_DIRECTORY=/nonexistent PYTHONPATH=. ncu --set full \
     --launch-count 1 --launch-skip 6 \
     -k regex:fused_decoder_megakernel_tc \
     -o /tmp/dec_d1024_ncu \
     python tuning/decoder_bench.py --d 1024 --B 16384 --reps 1 --warmup 6 --iters 2
   ncu -i /tmp/dec_d1024_ncu.ncu-rep --page details | less   # or --csv
   ```
   Look at: `sm__pipe_tensor_cycles_active.avg.pct_of_peak_sustained_active` (tensor-pipe
   utilization), `gpu__dram_throughput`, `sm__warps_active` (achieved occupancy), and
   the top warp-stall reasons (`smsp__average_warps_issue_stalled_*`).

   ENV CAVEAT (this box): ncu currently returns `ERR_NVGPUCTRPERM` — the container
   lacks permission to read GPU performance counters (needs host-level
   `NVreg_RestrictProfilingToAdminUsers=0` / `--cap-add` at container start, not
   changeable from here). `nsys` is not installed either. So the **clock64 phase
   timers (step 3) are the primary diagnosis instrument** — they need no special perms
   and gave the exact per-phase split. Use ncu (step 4) only if/when a profiling-
   enabled environment is available; until then the C7515 ptxas note (serialized
   wgmma — see build stderr) is the qualitative "why the GEMM is slow" signal.

## Guardrails — keep production green, instrumentation out of the prod path

- After ANY change to a shared header, prove production is still green BEFORE committing:
  ```
  CUDA_MPS_PIPE_DIRECTORY=/nonexistent PYTHONPATH=. python wiring_check.py --require-all
  ```
  must report **33/33 L3-TC**. (`_ops.so` only recompiles on `pip install -e .` /
  `setup.py build_ext`; a kernel-header edit alone does not, but rebuild + re-run the
  gate before committing a header change that the production TU includes.)

- `decoder_layout.cuh` d=128 (`#else`) branch must stay byte-identical to the committed
  history. Verify after a regen:
  ```
  python -m grokking_optimizers.megakernel_codegen --decoder-layout | \
    sed -n '/#else/,/#endif  \/\/ SG_DEC_BENCH_LAYOUT/p' | grep -E 'SG_DEC_D|kDecTotalElems'
  # must show SG_DEC_D = 128 and kDecTotalElems = 422755
  ```

- `SG_DEC_PROFILE` and `SG_DEC_BENCH_LAYOUT` are **never set on the production build**.
  They are passed only by `tuning/decoder_bench.py`. The committed kernel compiles them
  out by default (`#ifdef` / `#if SG_DEC_BENCH_LAYOUT` defaulting to 0).
