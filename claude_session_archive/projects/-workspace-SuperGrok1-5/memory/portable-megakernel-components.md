Owner (2026-06-09): the vit+sg2 single-binary persistent megakernel was an
EXAMPLE — the requirement is **all 3 models × 11 optimizers**, and the files
must be **individually portable into other projects seamlessly**. The
meta-programming belongs in header files; the dispatch file is the composition
seam. No CUDA graphs — true persistent megakernels (owner explicitly rejected
graphs as unnecessary and slower).

**Why:** the components are reusable building blocks beyond this repo; a third
project should lift substrate + one model-stage header + optimizer headers and
instantiate a fused trainer.

**How to apply:** the binding contract lives at
`csrc/fused/COMPONENT_CONTRACT.md` (component taxonomy, self-containment rules,
the out-of-tree "lift test", generated-artifact discipline). Per-model stage
headers (`model_stage_<model>.cuh`), not a monolith. `csrc/algorithms/<opt>.h`
are already the portable single-source math units. All cells + dispatch tables
generated by `megakernel_codegen.py` — never hand-edited. Every phase validates
portability by compiling a minimal TU that includes only the lifted headers.

Owner clarifications (2026-06-10): (1) perf optimizations must land IN the
component layers (substrate / model headers / opt headers) so all 33 cells
inherit via recomposition — never cell-specific hacks; (2) the TWO TUNERS are
separate systems: Optuna (`tuning/`) tunes OPTIMIZER hyperparameters for the
race; `compile.py`'s autotuner tunes KERNEL build params via
`_kernel_tuned.json` → `-DSG_TUNED_*` flags — never conflate them.
